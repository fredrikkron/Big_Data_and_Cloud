# Schedule and sensor in orchestration

**Schedule**

    Schedule means "run this job at a fixed time/interval" 
    Example - every day at 14:00

    It doesn't care if your upstream system is ready or not meaning it's time-driven and not data-driven

    Lights turn on in a room at a specific time
#

**Sensor**

    A sensor waits for a condition before triggering the job
    Example - run the dbt job when new data arrives in the system or when dlt job finishes

    Event/data-driven

    Depending on the tool sensors can block (keep running until ready) or deferrable (sleep until the condition is met)

    Lights turn on in a room when someone enters
#

# Schedule vs Sensor using dbt

    If a dbt job just needs to run at a fixed time a schedule is simpler and cheaper

    For example every 24 hour

    If the job depends on another data pipeline sensor is the safer option that ensures dbt doesn't start until data is ready

    For example having a dlt job that loads data into the warehouse
#

# Schedule vs Sensor using dlt

    Schedule

    If the data always arrives on time

    Sensor

    If data arrives at unpredictable times or if you want to avoid wasted runs when no data is available
