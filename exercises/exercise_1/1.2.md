# Running Python scripts locally with virtual environment activated

    - A virtual environment is like a "sandbox" for Python
    
    - When you activate it, the python scripts uses the packages and Python version inside that sandbox instead of the system-wide ones

    - This solves dependency problem which means that one project can run one version and another project a different version without conflict

    - However, everything else still runs on your machine
        Your operating system, libraries and environments = Host

#

# Running containerized Python scripts locally

    - A container (like with Docker) goes one level deeper where it doesn't only its own Python environment but also brings along its own OS-level dependencies, filesystem and isolated runtime

    - This means that you can run the exact same script with the exact same environment on Linux, Mac and Windows

    - Containers also allow you to define "what the environment should look like" making it reproducible for anyone (via a Dockerfile)
#

# Difference between a virtual environment and a uv virtual environment

**venv**

    - Creates a folder that has a copy of Python and a place for project-specific packages

    - You install dependencies using pip install

    - Every time you install packages it goes into that folder

    - Takes extra disk space and can feel slow because its kinda like making a new "mini-Python installation" for each project

**uv venv**

    - Modern, faster dependency and environment manager

    - Instead of copying Python binaries/installations, it can link or reuse them making creation much faster

    - It uses lockfiles and better caching so dependencies resolve consistently, gets tracked and a team always get the exact same version of libraries.
#

**venv**
    
    Like buying a brand-new toolbox every time you start a new project even if you have one in the garage

**uv venv**

    - Already have tools in my garage, use them again

    - When sharing a project you just hand over a shopping list (lockfile) so they get the exact same tools you used

# Containerization vs Docker

    Containerization is the general concept of packaging an application and all its dependencies so it can run anywhere (including OS-level ones)

    Docker is the most popular tool that makes the containerization easy (runtime and ecosystem)

### Difference

    Containerization is the idea of putting a meal in a lunchbox so you can eat it anywhere

    Docker is a famous brand of lunchboxes with lots of extra features
