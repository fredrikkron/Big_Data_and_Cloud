# Region and Availability Zone - Uptime of VM

### Region - A geographical area, VM run in that regions data centers

    - You get lower latency if you choose a region that is closer to your users
    - Uptime is dependent on the reliability of the chosen region - if the whole region goes down so does your VM
#

### Availability Zone (AZ) - A physical separate datacenter within the same region

    - If you place your VM in a specific AZ it gets isolated from failures in other zones
    - If deployment is done of multiple VMs across different AZ you get zone-redundancy which means higher uptime (you protect yourself from single datacenter failures)
#

    Region decides where your VM lives geographically
    
    Availability Zone increases resilience within the specific region by isolating VM from datacenter failures

# Resources created in Resource Group when creating VM

When creating an Azure VM, Azure usually provisions multiple resources inside your Resource Group to support it.

Typical resources that get created:

    - Virtual Machine (compute instance)
    - Network Interface - attaching VM to virtual network
    - Public IP Address (needs enabling) - allows external access
    - Network Security Group - firewall rules for controlling traffic inbound and outbound
    - Virtual Network - isolated network for VM
    - Subnet - logical subdivision of Virtual Network where VM resides
    - Disk(s):
        OS Disk
        Temporary Disk
        Data Disk
    - Diagnostic Storage/Log Analytics (if enabling monitoring)

At least 5-7 resources gets created when creation of VM is done
#

# Using Bastion to connect & Disk Size Check

Azure Bastion is a secure, browser-baed RDB/SSH service that connects to your VM without exposing a public IP

    RDB - Remote Desktop Protocal 
    SSH - Secure Shell

How to use:

    1. Enable Bastion in networking tab of VM
    2. Open Bastion connection in Azure portal
    3. Log in with VM credentials
    4. Remote desktop session opens directly in your browser

Disk Size Check inside the VM:

    1. When connected, open File Explorer, then right-click C:\ and press Properties -> Size of OS disk presented there
    2. Alternatively open Disk Management that shows OS Disk + Temporary Disk (D:)
        - OS Disk matches size chosen during VM creation
        - Temporary Disk is smaller and data is not persistent
